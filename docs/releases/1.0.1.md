# Prism Dashboard 1.0.1

This security update fixes local server impersonation in the optional Spotify
Liked Songs integration, reported in [marketplace submission #9726](https://github.com/omacom/omarchy-plugin-marketplace/issues/9726#issuecomment-6085838517).

Spotify now verifies the bridge's pinned public key before sharing track or
saved-song information or accepting an action. Each connection uses a fresh
encrypted session. Plaintext, altered, replayed, and previous-session messages
are rejected. The private bridge key stays in a user-owned directory with
mode 0700 and a file with mode 0600; only its public key is installed in Spotify.

## Upgrade the Spotify integration

Install Python cryptography and run the pairing script from the installed
Prism checkout:

```bash
omarchy pkg add python-cryptography
python3 integrations/spotify/pair-spotify.py
spicetify config extensions dashboard-spotify.js- extensions dashboard-spotify-auth.js
spicetify apply
```

The old extension entry must be disabled. Directly copying the unpaired source
does not enable the integration. See the [setup guide](../setup.md#spotify-heart)
for private dependency installs and custom paths.

Playback, artwork, calendar, and weather do not require Spotify pairing.
The heart retains confirmed, add-only behavior and cannot remove liked songs.

## Validation

The fake-server regression fails on the prior extension because it exposes
the current track before authentication. The updated extension passes that
check, forged-proof and altered-command checks, and replay rejection.
Independent Node crypto verifies WebCrypto interoperability. Real Soup
loopback tests verify encrypted actions and reconnects. Actual QML tests
verify confirmed saved-song state, add-only behavior, and unavailable controls.

A live check with desktop Spotify rejected a fake server on port 9154 with
no track disclosure. The installed widget then connected to the genuine
bridge and received saved-song status without adding or removing a song.

This fixes the reported impersonation path. It does not prevent a local
process from occupying the port or causing connection denial of service.
The [security reference](../spotify-security.md) describes these boundaries.
